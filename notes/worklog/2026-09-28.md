# Worklog 2026-09-28

## 当前目标
- 修复 Ingest MQTT 重连死循环：日志反复出现 `[CommunicationError] MQTT 接入连接异常: It is not allowed to connect with a server after the connection is established.`。根因是 `ConnectAndSubscribeAsync` 把「连接 + 订阅」当整体重试，连接已建立但订阅失败后，Polly 重试再次 `ConnectAsync` 于已连接的 client，被 MQTTnet 拒绝；连接永不关闭 → 后续每轮重连第一枪即失败。

## 落地内容
- 新增 `src/NitroCloud.Ingest/IngestMqttConnection.cs`：把连接/订阅抽为 `internal static ConnectAndSubscribeAsync(client, options, logger, ct)`；`client.IsConnected == true` 时跳过 `ConnectAsync`、只补订阅，否则先连后订阅。原方法从宿主服务移除。
- `src/NitroCloud.Ingest/MqttIngestHostedService.cs`：`ConnectAndSubscribeAsync` 改为转交静态实现的薄封装，行为不变（重试策略/循环由宿主保留）。
- `tests/NitroCloud.UnitTests/Ingest/IngestMqttConnectionTests.cs`：4 条单测（假 `IMqttClient`）——已连接跳过 Connect、未连接先连后订阅、连接非 Success 不订阅、订阅失败后仍连接时不重复 Connect（回归）。

## 验证
- 红绿对照：新增用例中「已连接跳过 Connect」与「订阅失败后仍连接不重复 Connect」在旧实现下会 Connect 两次/抛异常而失败；修复后全绿。
- `dotnet build NitroCloud.slnx`：0 错误（仅 Influx 既有 CS0618 过时警告）。
- `dotnet test NitroCloud.slnx --no-build`：UnitTests 118 通过、IntegrationTests 6 通过，全绿。
