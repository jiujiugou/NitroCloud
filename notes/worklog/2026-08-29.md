# 2026-08-29

## 当前目标
- 修复 Command 回写模块在 Docker 容器内连不上 EMQX：`docker-compose.yml` 的 `center` 只覆盖了 `Ingest__MqttHost: broker`，漏了 `Command__*`，导致 Command 回落 `appsettings.json` 的 `Command.MqttHost = "localhost"`（容器内指向自身，非 broker）。已在 `center.environment` 补 `Command__MqttHost: broker` / `Command__MqttPort: "1883"`（对齐 Ingest）；`docker compose config -q` 通过，渲染后两条 Command__ 已生效。此即 ADR-010 D7 / 2026-08-27 worklog 记录的已知遗留项。

## 三问
- 为什么做：回写命令发不出/收不到回执，根因是 Command MQTT 连错 broker。
- 验收标准：`docker compose config` 渲染出 `Command__MqttHost: broker`，容器内 Command 能连上 EMQX（重启 center 后日志见 "Command MQTT 已连接 broker:1883"）。
- 不做会怎样：DoD 5 回写闭环在容器部署下永远不可用，且日志误导（报连接异常而非配置错）。

## 定位与修复
- 现象：Command 在容器内报 MQTT 连接异常（`localhost:1883` 无监听）。
- 根因：compose 只配了 Ingest 的 broker 覆盖；Command 模块无环境变量覆盖 → 回落 appsettings.json 的 localhost。
- 改动（G1 已确认：部署配置行为修复，不动代码/库/依赖）：`docker-compose.yml` `center.environment` 补两行 `Command__*`。
- 验证：`docker compose config -q` EXIT=0；`docker compose config | grep Command__` 输出 `broker`/`"1883"`。

## 此前（今日早些时候）
- 修复线上 SQLite + EF Core 报错 `no such column: c.CommandId`（ADR-012）：根因是建表走 FluentMigrator（snake_case）而 EF Core 默认按属性名(PascalCase)生成列名。已在 `AppDbContext.OnModelCreating()` 加全局 snake_case 列名映射 + 集成回归测试（红绿对照通过）；`dotnet build NitroCloud.slnx` 0 警告 0 错误、`dotnet test` 全绿（集成 1/1 + 单测 92/92）。云端不动库、不删数据，更新 center 镜像重启即生效。

## 三问
- 为什么做：线上命令查询/写入报 `no such column`，启动即崩（启动扫描 in-flight 命令）。
- 验收标准：回归测试红绿对照通过 + build/test 全绿 + ADR/worklog 补齐。
- 不做会怎样：线上持续报错，且 sites/devices/points/alarm_records 的复合列随后也会以同样方式崩。

## 定位与根因
- 建表：`src/NitroCloud.Persistence/Migrations/M001~M005`（FluentMigrator，snake_case 列），`MigrationRunner.Run`→`MigrateUp`，用 `VersionInfo` 记版本——所以没有 `__EFMigrationsHistory`（正常，不是问题）。
- 映射：`AppDbContext.OnModelCreating()` 只配了表名/主键/长度/索引，从未配列名 → EF 按属性名生成 PascalCase 列（CommandId/SiteId/RequestedAt…）。
- 触发 SQL：`Sqlite/CommandStore.cs` `QueryInFlightAsync`（SELECT … WHERE Status IN ('Pending','Sent') ORDER BY RequestedAt）。
- 本地佐证：`src/NitroCloud.Api/nitrocloud.db` 5 张元数据表列名全 snake_case、无 command_records（本地未跑到 M005）、无 `__EFMigrationsHistory`。

## 改动（G1 已确认：数据模型映射行为变更；不动库、不删数据、不加依赖）
- `src/NitroCloud.Persistence/AppDbContext.cs`：`OnModelCreating()` 顶部加全局 snake_case 列名循环（`property.SetColumnName(ToSnakeCase(property.Name))`）+ 私有 `ToSnakeCase` 工具；`using System.Text`。
- `tests/NitroCloud.IntegrationTests/CommandStoreSnakeCaseMappingTests.cs`（新增）：FluentMigrator 建临时库 → 断言 EF 列名 = snake_case → CommandStore Add/QueryInFlight 往返；连接串 `Pooling=False` 避免连接池锁文件。
